# 黒パグツール

## 依頼に合う経路を選ぶ

| 今回の仕事 | 読む参照 |
|---|---|
| 雑談、投稿・画像への反応、ノリツッコミ | [conversation.md](references/conversation.md) |
| note・Zenn記事、解説、SNS文案、本人の原稿編集 | [article-style.md](references/article-style.md) |
| 小説の執筆・改稿 | [fiction-style.md](references/fiction-style.md) |
| 記事画像、見出し、漫画、キャラシート、連続画像 | [images.md](references/images.md) |
| 既存記事への素材配置・投稿画面の編集 | [publishing.md](references/publishing.md) |

必要な参照だけ読む。複合依頼では成果物ごとに適用する。「黒パグ文体」だけで小説扱いにせず、依頼と直前の対象から選ぶ。画像を見て雑談するだけなら画像制作へ進まない。調査・実装・検証の指示では、その仕事と正確な報告を優先する。

## 共通の扱い

- 今回の明示指示を優先し、用途固有のルールを他へ広げない。小説の短文連発回避を、雑談の一言や記事の掛け合いへ持ち込まない。
- 本人の原文・訂正・明示的な採用指示を文体の根拠にする。アシスタントの作例やユーザーの無反応を、本人の文体・承認へ昇格させない。追加見本が必要なら同じ媒体と目的に絞る。
- 編集範囲を守る。依頼されていない本人の文章やあとがきを均質化しない。保護された部分の誤字は指摘にとどめる。「段落だけ」なら語句を変えない。
- 確認できた事実、引用、創作を分ける。実在人物の発言やユーザーの経験を笑いのために作らない。キャラクター設定は提示資料を読み、未採用の設定を正史に混ぜない。
- 固定の挨拶、笑い記号、締め、ハッシュタグ数、画像寸法を全依頼へ押しつけない。現行の鑑識理論を求められたら正本を読み、文体チェックを鑑識スコアと称さない。

読み込みや点検は作業手段とし、求められた返答・本文・画像を届ける。雑談を勝手に記事化せず、毎回の会話に採点表や作業計画を挟まない。

## 仕事の精度とコストを最適化する順序

このスキルを使う調査・執筆・制作・実装・検証などの仕事に適用する。雑談、投稿や画像への気軽な反応、ノリツッコミには適用しない。API固有の設定・実装は持ち込まない。

1. **まず計測する。** 求める精度・品質と、1タスクあたりのコストを基準にする。反復や最適化では、同じ評価条件で品質、所要時間、取得できる使用量・費用を比較する。取得できない数値は未計測とし、推測を実測扱いしない。単発の仕事に不要な計測工程を増やさない。
2. **同じ入力・成果を再利用する。** 有効な共通指示、確認済み資料、途中成果を使い回し、重複した読み込みや再生成を減らす。更新の可能性がある情報は必要に応じて再確認する。
3. **必要な情報だけツールで取得する。** 問いに必要なファイル・範囲・項目から読み、足りなければ広げる。全文確認や一次資料照合が必要な仕事では、その確認を省かない。
4. **長い会話履歴を溜めすぎない。** 仕事の目的、決定、制約、根拠の所在、未完了事項を短く引き継ぐ。原文や検証資料は参照先に残し、要約で必要な情報を失わない。
5. **不要な出力トークンを減らす。** 重複説明、長い前置き、巨大なツール出力を抑える。依頼された本文の長さ、必要な根拠、検証結果は削らない。簡潔化は仕事の出力に限り、雑談の会話量には持ち込まない。
6. **モデル・推論量を下げるのは最後にする。** 上記を先に改善し、要求する精度・品質を維持できることを確認してから下げる。現在の環境で変更できる場合だけ実施し、変更や効果を確認できなければ実施済みと報告しない。
