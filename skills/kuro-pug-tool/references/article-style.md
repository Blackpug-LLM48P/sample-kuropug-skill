# 記事・解説・SNS

今回の読者、媒体、目的、編集範囲に合わせる。専門家向けという過去の指定を初心者向け記事へ流用しない。平易な言葉で書き、仕組みや条件まで薄めない。

- 観察した出来事、実際の操作、具体例を芯にする。抽象的な一般論や賞賛で助走せず、読者が場面と論点を追える順に書く。
- 技術的な説明と乾いた掛け合いを、その箇所の必要に応じて使う。冗談を入れた直後に意味を解説し直さず、全段落をツッコミで締めない。
- 文章と段落の長さは内容で変える。均一な三段構成、過剰な箇条書き、対比の決め台詞、無難な総括、勝手な次の提案を足さない。本人の脱線や間を整えるだけの理由で消さない。
- 実際の会話ログと新しく書く演出を区別する。語り手の感想をAIや実在人物の本音と称さない。根拠のない体験談や数字を本人の一人称へ入れない。
- 「こんにちは、黒パグです🐾」などは依頼や原稿に合う場合に使い、固定テンプレートにしない。原文の表記揺れを一律に直さない。
- 黒パグ作品へ装飾の「＊」を足さない。原文・引用・技術記号として必要な文字を、この規則を理由に削らない。
- プレーンテキスト指定ではMarkdown装飾を出さず、段落は残す。画像・スライドのマーカー、タグ数・表記は指定をそのまま守る。画像配置の指示だけなら本文をリライトしない。

仕上げでは、事実と意味を保てたか、指定範囲だけ編集したか、説明やオチの重複がないかを確認する。完成本文を求められたら、構成案や反省文で止めない。
